1. Code Quality High Impact 88 / 100
AreaObservationRating
Project Structure Clean separation: routers/, services/, models/, utils/. Single-responsibility per module. Static frontend isolated in public/. Excellent
Pydantic Schemas All request/response shapes are Pydantic v2 models with Field descriptions, min-length guards, and a typed Severity enum. Uniform error envelope (ErrorResponse) across all endpoints. Excellent
Router Consistency All six routers follow the same pattern: strip whitespace → validate → call service → return typed model or http_error_response. Predictable and easy to extend. Good
Configuration Settings class loads all env vars in one place with sensible defaults. Raises a clear RuntimeError at startup if ANTHROPIC_API_KEY is missing. .env.example is committed. Good
Logging Centralised get_logger() factory; namespaced under legallens.*; level controlled via LOG_LEVEL env var. Request middleware logs method, path, status, and duration for every call. Excellent
Frontend JS Modules are split by concern (api, storage, toast, upload, render). escapeHtml() helper used before any DOM insertion. crypto.randomUUID with a safe fallback. Clean ES module imports with no build step. Good
Maintainability Gaps No type hints on frontend JS. Inline <style> blocks in analyze.html duplicate rules from styles.css. requirements.txt pins no versions, which may cause reproducibility issues over time. Minor gaps
Documentation Comprehensive README.md with full API reference, deployment checklist, and smoke-test steps. Docstrings on all public Python functions and classes. Excellent
2. Security High Impact 80 / 100
AreaObservationRating
Secret Management ANTHROPIC_API_KEY is environment-only; never exposed to frontend JS. .gitignore excludes .env. README explicitly warns against committing secrets. Pass
CORS Policy CORS allow_origins is locked to a single configurable origin via CORS_ORIGIN env var. Dev default (localhost:8000) is intentionally restricted. Comments remind developers to update before production deploy. Good
File Upload Safety 10 MB hard limit enforced in both frontend JS and backend router. PDF processed entirely in-memory (io.BytesIO) — no disk writes. MIME type checked; non-application types rejected. Good
Error Leakage Unknown exceptions return a generic message via http_error_response; internal stack traces are never serialised to the client. Logged server-side only. Pass
XSS Prevention escapeHtml() is consistently used before inserting user-supplied strings (filenames, document labels) into the DOM. No innerHTML injection of raw API responses without escaping. Pass
AI Output Safety Legal disclaimer injected into every LLM prompt via LEGAL_DISCLAIMER_BLOCK. Risk explanations are required to use hedging language ("may be worth reviewing"). No prompt allows definitive legal verdicts. Excellent
Prompt Injection User-supplied document text is appended after structured system instructions. There is no explicit sanitisation of adversarial prompt injections within the document content itself. Partial
Rate Limiting / DoS No request-rate limiting or per-IP throttling is implemented. A malicious caller could exhaust the Anthropic API quota or overload the serverless function via repeated large-document submissions. Missing
Input Size (Text Path) The pasted-text path has no upper-bound on character count. Sending multi-megabyte strings will inflate prompt tokens and increase cost / latency without a safety ceiling. Gap
3. Efficiency Medium Impact 78 / 100
AreaObservationRating
PDF Extraction Processes PDF entirely in-memory using pypdf. No temp files created or disk I/O performed. Pure-Python — no native binary dependencies that could fail on serverless. Good
Anthropic Retry Logic Single retry on transient failure with a 1-second back-off. 60-second timeout prevents hung requests. Lazy client singleton avoids re-initialization on every request. Good
Frontend Caching Analysis results are persisted to localStorage keyed by document ID. Revisiting a document avoids redundant API calls for already-generated sections. QA history is preserved per session. Good
No Streaming LLM responses are fetched as complete payloads. For large documents (e.g. full contracts), this can lead to 15–20 s perceived wait times with no progressive rendering. Improvement possible
Token Usage max_tokens=4096 is set globally for all calls. Simpler features (checklist, QA) could use a lower ceiling to reduce latency and cost. No document truncation strategy for very large texts. Minor
Async Endpoints All routers are async def but the Anthropic client uses the synchronous SDK with time.sleep for the retry delay. This blocks the event loop on retry, reducing concurrency under load. Gap
Static Asset Delivery Static files are served by @vercel/static CDN, separate from the Python function — optimal for frontend assets. Fonts are loaded from Google Fonts with preconnect hints. Pass
Dependency Footprint Only 7 runtime dependencies; no heavy ML libraries. pypdf is pure-Python with no binary wheels. Frontend has zero npm packages or build tools. Excellent

Key Strengths

  • Comprehensive 269-test suite with full mock coverage
  • Clean layered architecture (routers → services → utils)
  • Legal disclaimer injected into every AI prompt by design
  • Uniform error envelope across all endpoints
  • API key never exposed to frontend; CORS locked by env var
  • In-memory PDF processing — no disk writes, serverless-safe
  • localStorage caching avoids repeated API calls
  • Strong ARIA coverage: tabs, live regions, landmarks, alerts
  • Zero npm dependencies — no build pipeline risk
  • Excellent README with deployment checklist

Improvement Areas

  • No rate limiting or per-IP throttling
  • Text input has no maximum-length ceiling
  • Synchronous SDK blocks async event loop on retry
  • No streaming — long waits for large document analysis
  • No automated frontend / E2E tests
  • Dependency versions not pinned in requirements.txt
  • Arrow-key tab navigation not implemented (ARIA pattern)
  • No prefers-reduced-motion media query
  • Prompt injection from document content not mitigated
  • Inline styles in analyze.html duplicate stylesheet rules
Prioritised Recommendations
  1. Add rate limiting — Implement per-IP request throttling on /api/analyze/* endpoints (e.g. slowapi or Vercel Edge middleware) to prevent quota exhaustion and abuse.
    Security · High Impact
  2. Cap text input size — Add a max character limit (~50,000 chars) on the pasted-text path in both the frontend and the router to prevent oversized prompts and uncontrolled cost.
    Security / Efficiency · High Impact
  3. Switch to async Anthropic client — Use anthropic.AsyncAnthropic and await the message call to avoid blocking the event loop on every LLM request, especially during retries.
    Efficiency · Medium Impact
  4. Pin dependency versions — Add exact versions to requirements.txt (e.g. fastapi==0.115.x) to ensure reproducible builds across CI and production deployments.
    Code Quality · Medium Impact
  5. Implement arrow-key tab navigation — Add Left/Right arrow key handlers with roving tabindex to satisfy the full WAI-ARIA Tabs pattern (WCAG 2.1 success criterion 2.1.1).
    Accessibility · Low Impact
  6. Add prefers-reduced-motion rules — Wrap spinner animation and toast transition in a @media (prefers-reduced-motion: reduce) block to respect user system preferences.
    Accessibility · Low Impact
  7. Add frontend unit tests — Write Jest or Vitest tests for storage.js, api.js, and render.js to close the gap in automated coverage for the client-side layer.
    Testing · Medium Impact
